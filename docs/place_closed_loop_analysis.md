# 放置闭环修正

放置闭环修正：从第 2 块起，夹爪到塔上方后先不松开，按腕部相机的识别结果移动，对正后再下降 `gap_place` 松开（[pick_place_flow.md](pick_place_flow.md) §2 第 7 ~ 9 步、§3）。第 1 块不修正，直接松开。

本文介绍现在有哪几种修正，每种消掉哪一项误差、留下哪一项，以及在 MuJoCo 仿真里测到的效果。

数据来源：

- 测量用的是 `feat/mujoco-sim@f53b16b` 的代码（2026-11-24）：在仿真里渲染测量，并跑完整流程的 e2e。
- 之后换了 DISCOVERSE 的模型，末端点也移到了指尖。`held_scale` 重新标定为 0.88（原来 0.86），其他数没有重测。
- 当时抓取区和塔之间的移动默认用规划场景（现在要加 `scene`）。这只影响回程会不会碰到塔（§4），不影响对正。

## 一览

叠塔时每一层的错位来自三项误差：

| 误差 | 是什么 |
|------|------|
| 抓取偏差 | 物块在夹爪里偏了：抓偏了，或松开时滑了一下 |
| 机械臂定位误差 | 指令点和末端实际到达的位置之差，包括随放置高度的漂移 |
| 对正残差 | 闭环停下时还差多少。停下条件有 2 px 的死区，且夹爪总从同一侧逼近，所以其中有一个每层都一样的系统偏差，下文叫死区偏差，约 1 mm |

现在有三种修正。后两种是可选项，都在第一种的基础上改，可以一起用：

| 修正 | 怎么打开 | 作用 | 留下的 |
|------|------|------|------|
| 对准塔顶物块（§2） | 默认：`pixi run pick-place go P1 P2` | 让夹爪对准塔顶物块，消掉机械臂定位误差 | 抓取偏差原样带到塔上。抓取偏差和死区偏差都留给上面所有层，逐层累加 |
| 看手里的物块（§3） | 视觉加 `--held-cube` | 让手里的物块对准塔顶物块，消掉沿两指空隙方向的抓取偏差 | 手指开合方向不修正；死区偏差仍逐层累加。需要标定 `expect_held_ref`、`held_scale`，真机上还没标定 |
| 不对称停下条件（§4） | 控制加 `place-stop ε` | 沿逼近方向剩余偏差小于 ε 才停，死区偏差从约 1 mm 降到约 0.57ε mm | 抓取偏差；调节的步数变多 |

作为对照，开环放置（`open-place`）不做修正：每块都去第 1 块的点，机械臂定位误差全部进入，抓取偏差不累加。

## 结论

- **默认的闭环只消掉机械臂定位误差。** 仿真里这项几乎为 0，所以仿真里开环比闭环齐：搭 8 块时，第 8 块相对底块开环偏约 0.35 mm，闭环约 2.1 mm。真机上这项有多大没量过，原作者在代码里记录过"高度增加时 x 方向前移"（§6）。
- **三种修正对准的都是下面一块。** 每层剩下的偏差会留给上面所有层：系统部分按层数线性累加，随机部分按层数的平方根增长（§1）。开环每块只相对指令点偏，不累加。
- **`--held-cube` 去掉了抓取偏差，单用时塔在仿真里反而更歪**：8 块偏约 10 mm，默认约 2 mm。原因是仿真里抓取偏差的均值（+1.1 mm）正好和死区偏差（−1.1 mm）抵消，去掉抓取偏差后只剩死区偏差逐层累加。这个抵消是巧合，真机上不一定有（§3）。
- **`place-stop` 去掉了死区偏差。** 单用时剩下抓取偏差逐层累加，8 块的运行在第 5 块后回程时碰倒了塔（§4）。和 `--held-cube` 一起用时 8 块偏 8.3 mm，剩下的三项（ε 的残差、视觉把手里物块的偏差估大了、松开时的滑动）同号（§5）。这两次都只各跑了一次。
- 换模型后五种方式的统一对比（每种一次，含人为抓偏）见 [放置方式对比](place_comparison.md)。

## 1. 误差模型：哪些误差会逐层累加

符号（都是基座坐标系里的水平位置，第 1 块在最底下）：

| 符号 | 含义 |
|------|------|
| gₙ | 松开第 n 块时末端点的位置 |
| cₙ | 第 n 块最后停在哪里 |
| eₙ = cₙ − gₙ | 抓取偏差：物块相对末端点的偏差，含松开时的滑动。均值 μ，标准差 σₑ |
| aₙ | 机械臂定位误差：指令点和实际末端点之差。随高度的漂移 d(z)，加随机部分 σₐ |
| b | 死区偏差：闭环停下时末端点相对塔顶物块中心还差多少的系统部分（死区、`expect_*` 标定误差） |
| rₙ | 对正残差的随机部分，标准差 σᵣ |

**闭环**（对准塔顶物块，第 2 块起）：相机装在 link6 上，对正的是相机和塔顶物块的相对位置，机械臂定位误差 aₙ 不进入：

gₙ = cₙ₋₁ + b + rₙ，所以 cₙ − cₙ₋₁ = b + rₙ + eₙ

**开环**：每块都去同一个指令点 G：

gₙ = G + aₙ，所以 cₙ − cₙ₋₁ = (aₙ − aₙ₋₁) + (eₙ − eₙ₋₁)

各项独立时：

| | 闭环 | 开环 |
|------|------|------|
| 相邻两层错位 cₙ − cₙ₋₁ 的均值 | b + μ | d(zₙ) − d(zₙ₋₁) |
| 相邻两层错位的标准差 | √(σₑ² + σᵣ²) | √2 · √(σₑ² + σₐ²) |
| 第 N 块相对底块 c_N − c₁ 的均值 | (N − 1)(b + μ) | d(z_N) − d(z₁) |
| 第 N 块相对底块的标准差 | √(N − 1) · √(σₑ² + σᵣ²) | √2 · √(σₑ² + σₐ²) |

要点：

- 闭环去掉的是 aₙ：机械臂的重复定位误差和随高度的漂移。
- σₑ 和 μ 在闭环里一项都没有被减掉。闭环把"这一块相对上一块"的误差从 eₙ − eₙ₋₁ 换成了 eₙ + b + rₙ：去掉了上一块的抓取偏差，换来了对正残差，并且这一块的偏差会一直留给上面所有层。
- μ（抓取的系统偏差，比如 `expect_pick_ref` 标得不准）在开环里只让整座塔平移，在闭环里每层累加一次，塔变成台阶。
- 只看抓取偏差时：相邻两层的错位，闭环是开环的 1/√2（小 29%）；塔顶相对底块的偏移，闭环是开环的 √((N − 1)/2) 倍，8 层时 1.9 倍。

单看一块的抓取偏差 δ（第 n 块抓偏了 δ，其他块都没偏）：

| | 第 n 块相对第 n − 1 块 | 第 n + 1 块相对第 n 块 | 塔顶相对底块 |
|------|------|------|------|
| 闭环 | δ | 0 | δ（上面所有层跟着第 n 块走） |
| 开环 | δ | −δ | 0（第 n 块是顶时为 δ） |

两种方式都没有减小 δ 本身。闭环让 δ 只出现在一个接缝上，但传到塔顶；开环让 δ 出现在两个接缝上，但不传到塔顶。

§3、§4 的两个可选修正分别去掉 eₙ（沿两指空隙方向）和 b，但闭环对准的仍是上一块，剩下的每一项照样按上表累加。

## 2. 对准塔顶物块（默认）

### 2.1 视觉看到什么

`Best_Contour.py` 在 Place 阶段按塔顶物块的颜色过滤（手里的物块是另一种颜色），只保留第 423 行以上、`place_crop_x` 以内的部分，发出两个量：

- x：塔顶物块中心相对 `expect_x`；
- y：塔顶物块的图像上边沿相对 `expect_place_ref`。代码里叫"上边沿"（`upper_edge`），指图像里最上面的那条边，实际是物块的下边沿；下文都写"图像上边沿"。

两个量都只和"相机与塔顶物块"的相对位置有关。在仿真里固定夹爪和塔，只移动手里的物块，用和 `Best_Contour.py` 相同的识别代码（`sim/calib_vision.py` 的 `detect`）测：

| 移动的东西 | 移动量 | 塔高 1 / 3 / 6 块时识别结果的变化 |
|------|------|------|
| 手里的物块，沿基座 x（两指之间的空隙方向） | ±2、±4 mm | 0 px（只有一次 +0.5 px，是像素取整） |
| 手里的物块，沿基座 y（手指开合方向） | ±2、±4 mm | 0 px |
| 塔顶物块，沿基座 x | ±2 mm | 图像上边沿 y：−1.5 ~ −1.75 px/mm |
| 塔顶物块，沿基座 y | ±2 mm | 中心 x：−1.75 ~ −1.88 px/mm |

下文取 **1.75 px/mm**。Pick 阶段扫描位姿上同样是 1.75 px/mm。仿真相机的安装位置取自 DISCOVERSE 的模型（`configs/scene/sim.yaml` 的 `camera`），和真机是否一致没有核对。

### 2.2 消掉什么、留下什么

- **消掉机械臂定位误差。** 对正的是相机（装在 link6 上）和塔顶物块之间的相对量，机械臂到了哪里、和指令点差多少都不影响结果。
- **不消抓取偏差。** 手里的物块在夹爪里移动 ±4 mm，识别结果不变（§2.1）。夹爪对准塔顶物块后，这一块的抓取偏差原样留在这一层，并传给上面所有层（§1）。
- **留下死区偏差。** 见 §2.3，每层约 1 mm，方向固定，逐层累加。

### 2.3 停在哪里：死区偏差

停下条件（`_Place_and_Go`）：切换阶段后跳过 3 帧，之后 |dx| < 2 px 且 |dy| < 2 px，等 0.5 s 后下一帧仍满足才松开。

- **死区**：2 px ÷ 1.75 px/mm ≈ **1.14 mm**（每个轴）。
- **从一侧逼近**：从第 2 块起，去程（第 4 ~ 6 步）到 (`place_position_x`, `place_position_y`)，塔在它沿夹爪 z 轴 +1 cm 处，所以起始偏差约 10 mm（17.5 px），总是从同一侧靠近。
- **每一步走多少**：每像素 1/(100 · `control_param2`) m。1 px 对应 0.57 mm，每一步消掉的比例（增益）就是每像素走的距离除以 0.57 mm：

  | `control_param2` | 每像素走 | 每步消掉的比例 | 进入死区时离边界 | 停下时剩的偏差 |
  |------|------|------|------|------|
  | 100（e2e 用的值） | 0.10 mm | 0.175 | 一步约 0.35 px | 约 1.65 ~ 2 px，即 0.95 ~ 1.14 mm |
  | 40.51（README 里的真机示例） | 0.25 mm | 0.43 | 一步约 0.86 px | 约 1.1 ~ 2 px，即 0.65 ~ 1.14 mm |

  增益小于 1，不会越过目标，所以停在逼近一侧的死区边缘附近。

所以 b 沿逼近方向约 −1 mm，方向固定（朝去程目标点一侧）。另一个轴起始偏差小，停在死区里的位置取决于起点，b 的这一分量较小。rₙ 来自识别的像素取整（±0.5 px，约 0.3 mm）和停下前最后一步的位置。

`expect_place_ref`、`expect_x` 标得不准时，b 再加上标定误差，每像素 0.57 mm，同样每层累加。

### 2.4 仿真结果

两次 e2e 运行（地面场景，`configs/control/sim.yaml`，`control_param2` = 100，各搭 8 块）：

- 闭环：`pixi run test-e2e floor --blocks 8`，`runs/e2e/floor_20261124_171158`；
- 开环：`pixi run test-e2e open-place --blocks 8`，`runs/e2e/open-place_20261124_171533`。

从每块松开前的末端位置（gₙ）和最后物块的位置（cₙ）拆出各项，单位 mm，基座坐标系，x 是两指之间的空隙方向，y 是手指开合方向：

| 量 | 闭环 | 开环 | 对应模型里的 |
|------|------|------|------|
| 物块相对末端点 eₙ，均值 | (+1.13, −0.54) | (+1.12, −0.43) | μ：两次相同，和放置方式无关 |
| eₙ 的标准差 | (0.51, 0.18) | (0.48, 0.13) | σₑ：两次相同 |
| 末端点相对上一块 gₙ − cₙ₋₁，均值 | (−1.10, +0.28) | — | b：x 是死区边缘（§2.3 预计 −0.95 ~ −1.14） |
| 开环末端点相对第 1 块 gₙ − g₁，最大 | — | 0.03 | aₙ：仿真里机械臂几乎没有定位误差 |
| 相邻层错位的均值 | (+0.09, −0.28) | (+0.03, −0.04) | 闭环 b + μ，开环 0 |
| 第 8 块相对底块 | (+0.65, −1.96) | (+0.24, −0.26) | 闭环 y：7 × (−0.28) = −1.96，正好是线性累加 |

读法：

- 抓取偏差 eₙ 在两种方式下一样，闭环没有减小它（§2.1 的结论在完整流程里也成立）。
- 闭环 x 方向：b ≈ −1.1 mm 和 μ ≈ +1.1 mm 正好抵消，所以没有台阶。b 的方向由放置点那 1 cm 的方向决定，μ 来自抓取（Pick 阶段的停止死区 |dx| + |dy| < 5 px 或 `expect_pick_ref` 的标定，这里没有拆开），两者抵消是巧合。
- 闭环 y 方向：b + μ ≈ −0.28 mm，没有抵消，8 块累加到 −1.96 mm。
- 仿真里 aₙ ≈ 0，默认的闭环能消掉的那一项不存在，所以开环更齐。这说明不了真机。

每层系统偏差 s = b + μ 不同时，闭环第 N 块相对底块偏 (N − 1)s。塔不倒要求上面各块的重心落在下面一块上，对等差台阶这等价于 s · N < 25 mm（物块边长）：

| s（每层） | 来源举例 | 第 8 块相对底块 | 不倒的最多块数 |
|------|------|------|------|
| 0.28 mm | 仿真 y 方向实测 | 2.0 mm | 89 |
| 1.1 mm | 只有死区偏差，μ = 0 | 7.7 mm | 22 |
| 2.2 mm | 死区偏差和抓取偏差同向 | 15.4 mm | 11 |

开环没有这一项，每层相对指令点的偏差不随层数增长。

## 3. 看手里的物块（`--held-cube`）

**做法**（[pick_place_flow.md](pick_place_flow.md) §3）：Place 阶段除了塔顶物块，还识别手里的物块：另一种颜色、`place_crop_x` 以内、下边最低的轮廓（不按第 423 行裁剪）。它的图像上边沿（实际是挨着塔顶的下边沿）相对 `expect_held_ref` 偏了多少，乘上 `held_scale` 后加到 `expect_place_ref` 上，再算塔顶物块的 y 偏差。

- 这样沿两指空隙方向对正的是手里的物块和塔顶物块，不是相机和塔顶物块，抓取偏差 eₙ 也进入闭环。
- 只修正两指之间的空隙方向（图像 y）。手指开合方向（图像 x）上夹紧时手指会把物块推到中间，先不纳入。
- 看不到手里的物块时这一帧不发偏差，机械臂停在原地。控制程序不需要改动。

**标定**：`pixi run sim-calib-vision --apply` 算出 `expect_held_ref`（物块在夹爪正中时的图像上边沿）和 `held_scale`（沿两指空隙方向同样的位移，塔顶物块和手里物块在图像 y 上移动的像素之比）。测量时手里物块每 mm 在图像 y 上移动 1.85 px，塔顶物块 1.60 px/mm，所以 `held_scale` = 0.86；换模型后重新标定为 0.88。真机上还没有标定，方法见 `configs/vision/real.yaml` 里的注释。

**静态检查**（渲染，塔高 4 块，夹爪放在"手里物块正好对准塔顶物块"的位置；当时两个方向都修正）：抓偏 ±3 ~ 5 mm 时，不修正的偏差为 4 ~ 8 px，修正后在 1.2 px（0.7 mm）以内。

**完整流程**（地面场景，各搭 8 块，`control_param2` = 100）：

| | 闭环（`floor`） | 闭环 + `--held-cube`，两个方向都修正 | 闭环 + `--held-cube`，只修正两指空隙方向 |
|------|------|------|------|
| 第 8 块相对底块 | 2.1、2.4 mm（两次） | 10.1、10.1、10.7 mm（三次） | 10.6 mm |
| 相邻层错位，两指空隙方向 | 平均约 +0.1 mm | 每层 −1.7 ~ −2.2 mm | 每层 −1.4 ~ −2.1 mm |

记录了物块在夹爪里真实位置的两次运行（`held-cube_20261124_182517`、`held-cube_20261124_183303`），第 2 ~ 7 块，两指空隙方向：

- 物块在夹爪里偏 +0.8 ~ +1.3 mm，比标定时低 0 ~ 0.5 mm。视觉估计的偏差约 +1.4 mm，略大（物块偏低也让图像上边沿上移，每 mm 约 1 px）。
- 松开前手里物块相对塔顶物块偏 −0.7 ~ −1.6 mm，每层几乎一样。抓取偏差确实被去掉了：图像里对到固定的像素位置，两块的相对位置就固定。但这个固定的相对位置不是 0，而是死区偏差 b ≈ −1 mm（§2.3）：停下条件是 |dy| < 2 px 而不是 dy = 0，且总从同一侧逼近，所以每次停在同一侧的死区边缘。每层都偏同样的 b，第 N 块相对底块就偏 (N − 1)b。
- 松开时物块又沿同一方向滑了 0.2 ~ 0.9 mm（塔已经成台阶，第 8 块时手里物块倾斜 0.9°）。

**作用**：每层的错位从 b + eₙ 变成 b，再加上视觉估计误差和松开时的滑动。

- 随机部分（σₑ）总是有回报：不再按 √(N − 1) 传到塔顶；某一块抓偏了几毫米，也不会再传给上面所有层。
- 系统部分：原来每层偏 b + μ，现在偏 b。μ 和 b 同号、或 |μ| > 2|b| 时有回报；μ 和 b 反号且 |μ| < 2|b| 时原来更好，因为两者部分抵消。
- 仿真正好是后一种情况里最极端的：μ ≈ +1.1 mm，b ≈ −1.1 mm，完全抵消（§2.4）。σₑ 只有 0.5 mm，随机部分的回报（第 8 块约 √7 × 0.5 ≈ 1.3 mm）远小于失去抵消的损失（7 × 1.1 ≈ 7.7 mm），所以塔反而更歪。
- 真机上 μ、σₑ 都没量过（§6），μ 和 b 是否也抵消没有依据。同时用 `place-stop` 去掉 b（§4、§5）后，`--held-cube` 不论 μ 是多少都更好。

## 4. 不对称停下条件（`place-stop ε`）

**为什么默认的停下条件留下死区偏差**：增益小于 1、总从同一侧逼近时，剩余偏差单调减小、不越过 0，所以只有逼近一侧的死区边界起作用，另一侧永远碰不到（§2.3）。

- 所以"前后不对称、每层交替"的死区（`Best_Contour.py` 里原作者的注释提过"上下轮换逼近"）不会让 b 换号：逼近侧小的那些层停在 0 附近，逼近侧大的那些层停在大的边界，b 同号，平均值照样累加；小的一侧如果在远侧则根本碰不到。
- 把死区整体改小也能减小 b，但远侧也变小后，识别噪声造成的小幅越过会让夹爪来回调。

**做法**（`airbot_play_rules.place_aligned`）：不对称死区每层都用，逼近侧为 ε（很小），远侧放宽，也就是"沿逼近方向剩余偏差一降到 ε 以下就停"。把 (dx, dy) 分解到逼近方向 u（放置姿态下末端 z 轴的水平方向，即两指之间的空隙方向）和它的垂直方向，满足 −2 px < d·u < ε 且 |d·u⊥| < 2 px 时停下。

- 远侧和横向保持 2 px。远侧放宽的好处是噪声造成的小幅越过也立即停下，不会来回调。
- b 从约 1 mm 降到约 0.57ε mm。这和把 `expect_place_ref` 朝逼近侧挪一个死区宽度等价。
- 只有逼近方向（两指空隙方向，图像 y）能这样做；手指开合方向（图像 x）起始偏差小、逼近方向不固定，仍用对称死区。

**代价是步数**（从 17.5 px 开始，每步消掉的比例为 g）：g = 0.175 时，ε = 2 / 1 / 0.5 px 分别约 11 / 15 / 19 步；g = 0.43 时约 4 / 5 / 6 步。ε 不能取 0：识别结果以 0.5 px 为单位，比例控制只会无限接近 0。

**冒烟测试**：只加 `place-stop 0.5`（`place-stop_20261124_210751`），跑一次 8 块，只确认能跑通，不作为对比结论（对比见 §8）。

- 死区偏差去掉后只剩抓取偏差 μ ≈ +1 mm，塔每层向 +x（逼近方向）偏 0.5 ~ 1.3 mm，第 5 块比第 1 块偏 3.6 mm。
- 放好第 5 块回抓取区时右手指擦到塔顶，塔倒了。当时回程用规划场景：场景里的塔在第 1 块的位置（+10 mm），四周放大 1 cm；第 5 块在 +14.2 mm，仍在碰撞体里，离碰撞体的面还有约 6 mm。也就是说，塔的倾斜用掉了 1 cm 余量里的约 4 mm，剩下的约 6 mm 被回程实际走的路径和规划的路径之差用掉了（回程限速系数 1.0，最快；没有记录关节角，没有核实）。`floor` 运行里同一段回程离塔的最小距离也只有 9 ~ 11 mm，说明规划路径常贴着碰撞体走。
- 之后把塔的碰撞体沿两指空隙方向两边各加长一个边长（[pick_place_flow.md](pick_place_flow.md) §4），塔怎么斜都还在碰撞体里，1 cm 余量全部留给其他偏差。现在默认的固定路点回程不用碰撞体，放好后侧移 7.5 cm；塔斜了以后会不会碰到，还没有测过。

## 5. 两项一起用（`--held-cube` + `place-stop ε`）

`--held-cube` 去掉抓取偏差，`place-stop` 去掉死区偏差，两项一起用时每层剩下的只有对正和测量的误差。

冒烟测试（`held-cube-stop0.5_20261124_212654`，ε = 0.5，跑一次 8 块）：塔没被碰，第 8 块相对底块 8.3 mm（只加 `--held-cube` 时 10.1 ~ 10.7 mm）。第 2 ~ 8 块，两指空隙方向：

- 松开前手里物块相对塔顶物块平均 −0.71 mm（只加 `--held-cube` 时 −0.88 mm）。其中约 0.3 mm 是 ε = 0.5 px 的残差；其余约 0.4 mm 是视觉把手里物块的偏差估大了（真实 +0.9 mm，视觉约 +1.4 mm）：手里物块的图像上边沿取的是外接矩形的整数行，1 px 约 0.54 mm，物块在夹爪里还比标定时低 0 ~ 0.5 mm。
- 松开时物块又沿同一方向滑了平均 0.45 mm。
- 两项同号，每层合计约 −1.2 mm，所以仍是台阶。

## 6. 真机上缺的数

| 量 | 真机上知道多少 |
|------|------|
| σₑ、μ（抓取偏差） | 没量过。上限：Pick 在 \|dx\| + \|dy\| < 5 px 时下抓，沿两指空隙方向最多偏 5 px ≈ 2.9 mm（按仿真的 1.75 px/mm），再加 `expect_pick_ref` 标定误差和松开时的滑动。手指开合方向上，夹紧时会把物块推到中间 |
| aₙ（机械臂定位误差，随高度的漂移） | 没量过。旧代码有两处注释说存在：`go_to_place_pose` 里"实机当高度增加时，会出现 x 方向前移的问题"，以及第 1 块多放 1 cm 的原因"放置卡位造成 xy 无法到达目标" |
| b（死区偏差） | 死区 2 px 和逼近方向两边相同，约 1 mm；再加真机 `expect_place_ref` / `expect_x` 的标定误差 |
| px/mm | 按相机安装位置应和仿真接近，没量过 |
| `expect_held_ref`、`held_scale` | 没标定，真机上还不能用 `--held-cube` |

默认的闭环比开环齐（第 N 块相对底块），当且仅当

(N − 1)² (b + μ)² + (N − 1)(σₑ² + σᵣ²) < (d(z_N) − d(z₁))² + 2(σₑ² + σₐ²)

需要在真机上量的就是右边的 d(z)、σₐ 和两边都有的 μ、σₑ。一个办法：开环搭一座塔，量每块相对底块的偏移，减去手里物块的偏差（松开前从侧面拍一张），剩下的就是 aₙ。

## 7. 还没做的修正

- **对准底块而不是上一块**：每层都对准第 1 块的位置（相当于开环指令点 + 视觉修正机械臂误差），偏差不累加。但需要看到被遮住的下层物块，或者记录第 1 块的位置后用机械臂的正解。
- **手指开合方向也看手里的物块**：夹紧时手指会把物块推到中间，所以先没做。§3 的完整流程里，两个方向都修正（10.1 ~ 10.7 mm）和只修正两指空隙方向（10.6 mm）看不出差别。

## 8. 对比实验

2026-11-27 做了，见 [放置方式对比](place_comparison.md)：五种方式（闭环、开环、`--held-cube`、`place-stop 0.5`、两项一起）各搭 8 块，分不加干扰和每块人为抓偏 2 ~ 3 mm 两种条件，比较最终的塔；转移方式（固定路点、规划场景）各录一段像。每种只跑了一次。
